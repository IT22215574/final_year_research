# Fish Trip Cost Active Flow

## 1. Fisher Mobile Prediction Flow

1. Mobile planner screen:
   - `mobile/app/(root)/(tabs)/fishtripcost/planner.tsx`
   - main UI component: `mobile/app/(root)/(tabs)/fishtripcost/components/TripPlanner.tsx`
2. User selects boat and enters route/weather/cost inputs.
3. Mobile service sends:
   - `POST /api/v1/cost-engine/predict`
   - from `mobile/services/tripService.ts`
4. Backend prediction runs in:
   - `Backend/src/cost-engine/cost-engine.controller.ts`
   - `Backend/src/cost-engine/cost-engine.service.ts`
5. Backend optionally calls FastAPI ML service:
   - `POST http://localhost:5001/predict/fuel`
   - `POST http://localhost:5001/predict/profitability`
   - service root: `model/cost_prediction/app.py`
6. Backend returns prediction with:
   - distance
   - weather severity
   - predicted fuel
   - fuel/operational/external/total cost
   - carbon
   - profitability/risk
   - recommendations
   - active model metadata when `ENABLE_MODEL_VERSION_ROUTING=true`
7. Mobile result screen displays prediction:
   - `mobile/app/(root)/(tabs)/fishtripcost/result.tsx`

## 2. Save Trip And Actual Learning Flow

1. Result screen save calls:
   - `POST /api/v1/cost-engine/predict-and-save`
2. Backend saves the planned trip in MongoDB using:
   - `Backend/src/schemas/trip.schema.ts`
3. Fisher logs actual fuel/catch:
   - `mobile/app/(root)/(tabs)/fishtripcost/log-actual.tsx`
   - `POST /api/v1/trips/:id/log-actual`
4. Backend:
   - marks trip completed
   - calculates predicted vs actual metrics
   - updates boat adaptive coefficients through FastAPI `/learning/update`
   - creates a pending `TrainingCandidate` when `ENABLE_GOVERNED_TRAINING_PIPELINE=true`

## 5. Boat Type Naming And Fuel Units

Active boat type codes should stay as:

- `IMUI`
- `IDAT`
- `OFRP`
- `MTRP`

Use display names only for UI labels. Store and train with the codes above so
mobile, backend, Colab notebooks, model folders, and FastAPI lookup all resolve
the same boat-type model.

Fuel baselines must keep separate units:

- `fuelPerKm` / `baselineFuelPerKm` = route fuel in `L/km`
- `fuelPerHpHour` / `baselineFuelPerHpHour` = engine-hour fuel in `L/HP/hour`

Do not place real-world `L/HP/hour` values such as `0.28` into a field named
`fuelPerKm`. That mixes physical units and breaks prediction explanations.

The fallback formula should be:

```txt
route_fuel = distanceKm * fuelPerKm
fishing_fuel = engineHP * fishingHours * fuelPerHpHour * engineLoadFactor
fuel = (route_fuel + fishing_fuel) * weather/speed/learning adjustments
```

Trained boat-type models remain the primary prediction path. These baselines are
for fallback, blending, explainability, and cold-start behavior.

## 6. Weather Data And Weather Severity

Weather for fish-trip cost prediction should be route-aware, not only one
position. The mobile planner uses selected fishing zones as route samples:

```txt
selected zones -> weather per zone -> route weather summary -> backend WSI
```

Weather source split:

- Open-Meteo Forecast API: `wind_speed_10m`, `precipitation`,
  `temperature_2m`
- Open-Meteo Marine API: `wave_height`

This split is important because wave height is a marine variable, while wind and
rain come from the weather forecast API.

Route summary logic. When zone distance is available, averages are weighted by
that route distance:

```txt
route_wind = 70% distance-weighted average zone wind + 30% maximum zone wind
route_wave = 70% distance-weighted average zone wave + 30% maximum zone wave
route_rain = 70% distance-weighted average zone rain + 30% maximum zone rain
```

This avoids a weak single-position estimate and still accounts for one rough
segment increasing fuel/risk.

Backend weather severity uses these units:

- `windSpeed`: km/h
- `waveHeight`: meters
- `rainMmPerHour`: mm/hour

WSI normalization:

```txt
windN = windSpeed / 60
waveN = waveHeight / 4
rainN = rainMmPerHour / 25
wsi = 0.40 * windN + 0.45 * waveN + 0.15 * rainN
```

The resulting `weatherSeverityIndex` is sent to the Python fuel model and stored
with the trip for future training candidates.
